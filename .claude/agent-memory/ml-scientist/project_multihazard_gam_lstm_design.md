Design consult (2026-07): widen the psi flood covariate (impute_flood_probability.R, EMDAT `Disaster Type=="Flood"` only) to include tropical cyclone + storm surge, and maybe drought (disease-modeler confirming cholera-relevance). My lane = GAM architecture + LSTM feature representation.

**Why: hazards have opposite-sign climate drivers** (flood=high antecedent precip/soil-moisture; cyclone=wind+coastal; drought=LOW precip/SPEI deficit) → a single additive binomial GAM (`logit P = Σ s(x_j)`) cannot coherently fit them. Hard evidence: mixing cyclones into the flood label un-neuters `s(wind_speed_10m_max)` (edf 0.74→1.99) — the GAM can no longer keep the storm channel quiet because it must explain events precip can't. `by=region_f` does NOT rescue this (confound is hazard-type, not region).

**How to apply — VERDICTS:**
- **Q2 GAM:** SEPARATE GAMs. Flood = keep as-is (cyclone-benchmark-validated, do not touch label/formula). Cyclone-surge = separate binomial GAM, wind/coastal-centric, low-k + `select=TRUE`, keep iso RE. ~62 cyclone weeks is sparse-but-OK for a deliberately-low-EDF fit; gate on the existing rolling-year CV AUC<0.65 warning — if it can't clear ~0.65, THEN merge cyclone into flood label (decide empirically). Drought = do NOT build standalone GAM (slow/wide/non-episodic → 149 point-events fit a flat climatological prior = the flat-signal trap; SPEI already in flood GAM as bidirectional `s(spei_approx)`); gate on disease-modeler + CV. Never a merged all-cause GAM.
- **Q3 LSTM channels:** SEPARATE but LEAN, never merged `hazard_prob` (merge collapses coastal-cyclone vs inland-flood, discards what the GAMs encoded + kills per-country conditioning value). Do NOT mirror the 8-feature flood block per hazard (+16 = ~42% input-width blowup into the overfit wall). Lean: cyclone = `prob` + `prob_12w_max` (2; punctate → no anom-lag ladder); drought = `prob` + one slow integrator (1-2; slow → level+integrator is correct). Flood keeps its validated 8. Defensible budget **+3 to +6 total**, NOT +16. Shipping ZERO new features is a legit likely outcome (flood block may already span shared antecedent-precip signal).
- **Q4 FiLM:** hazards STAY trunk main-input; NO hazard-specific FiLM. Existing country/region FiLM (`z_c=(1+γ_c)z_r+β_c` on 32-dim trunk output, zero-init country-dev embedding + partial-pool L2) ALREADY does per-country affine re-weighting of the pooled hazard+climate response — an explicit C×H FiLM gate overfits country embeddings to episodic noise. Escalation only if CV wins AND γ_c saturates on coastal/arid: add a static per-country exposure covariate (coastal frac, aridity) as 1-2 main-input features the existing FiLM conditions on — NOT new FiLM weights.

**Validation plan (screen like v7.3 was screened):** register arms in feature_sets.R (v7.3 control / +cyclone_lean / +cyclone_drought_lean / +hazard_full[expected loser] / +cyclone_merged[merge null]); ≥3 rolling-origin cutoffs via `.psi_make_rw_cv_steps` (4wk embargo); rank on **cross-country Pearson + WIS-skill vs seasonal-climatology** (evaluate_rolling_cv emits wis_skill_*/mae_skill_*) — NOT MAE (MAE rewards flat/under-predict psi, penalizes real episodic amplitude). 5-seed logit-pooled, serial on all_mosaic. LEAKAGE GATE: each fold's hazard GAM must be fit within-fold (`year<cutoff`), else imputed prob peeked at post-cutoff EMDAT labels = leakage even w/ realized climate (cf [[project_forecast_cv_leakage_redteam]]). Watch downstream psi_star attenuation ([[project_oos_2024_10_suitability_investigation]]) — validate at psi level. Consistent with [[project_psi_flat_flood_windows_fit_latency]]: flood already strongest-surviving screening class as trunk input; weak-signal ceiling (no NN beats seasonal_naive) means "add nothing" is on the table.
