# PROTOCOL — autonomous evolution of est_suitability() for 12-week forecast skill

**Mode: FULLY AUTONOMOUS with written stopping rules.** Agents propose, launch, score, adopt and
iterate without per-wave approval, reporting asynchronously. That makes the guardrails in §5 the
load-bearing part of this document, not boilerplate: an agent that both proposes and adopts will
drift toward whatever it can measure unless the objective is frozen and the harness is
continuously falsified.

**Objective:** `OBJECTIVE.md` (frozen, **v3** — anchored on the production validation grid).
**Ledger:** `REGISTRY.tsv` (append-only). **Queue:** `BACKLOG.md`.
**Incumbent:** the arm named in `INCUMBENT` at the top of `REGISTRY.tsv`.

**What changed at v3 (2026-09-18), and why.** Waves 0-20 produced four rejections and one
transferable finding: **every refit-arm delta in the v2 ledger was smaller than the spread between
two fits of the same arm** (0.070 seed / 0.159 residual). The instrument could not resolve the
effects being sought. v3 keeps the machinery that earned its place and fixes the three things that
caused that:

1. the grid is re-anchored onto the **9 cutoffs where production psi is already frozen** (the
   incumbent becomes ~free, and 9 origins rather than 18 halves per-arm cost);
2. the freed budget is spent on **resolution** — production seed counts and a measured noise floor
   per arm class (§3b) — rather than on coverage;
3. **refit-class arms become first-class** (inner-CV geometry, architecture, data), which is what
   waves 0-20 could not evaluate and what this programme now exists to evaluate.

---

## 1. The unit of work: a WAVE

One wave = one batch of arms taken to a decision. Target 4-6 h wall on dugong.

```
0 FLOOR       the applicable fit-noise floor for this arm's CLASS and SEED COUNT must
              already be measured (§3b). If it is not, that measurement IS the wave.
1 SELECT      pick arms from BACKLOG per the policy in §2
2 PREREGISTER append one REGISTERED row per arm BEFORE any fit runs:
              arm_id, parent, one-line hypothesis, the ONE change vs parent, arm CLASS,
              predicted direction (+/-/0), spec hash, n_seeds, objective_version
3 RUN         launch on dugong under the budget in §6
4 SCORE       compute S(arm) on SELECTION blocks only; write SCORED row
5 GATE        apply §3 A1-A6; if any fails -> REJECT and stop here
6 CONFIRM     score on the LOCKED confirmation blocks; write CONFIRMED row
7 REVIEW      adversarial pass (§4) by an agent that did not run the arm
8 DECIDE      ADOPT (incumbent := arm) or REJECT, with reason, appended to REGISTRY
9 PROPAGATE   an ADOPTED arm, and only an adopted arm, goes to stage 2 (OBJECTIVE §6)
10 PROPOSE    append new candidate arms generated by what was learned to BACKLOG,
              each with a hypothesis, a class and a predicted direction
```

**No step may be skipped or reordered.** An arm with no REGISTERED row predating its SCORED row is
void. An arm whose CONFIRMED row predates its SCORED row is a protocol breach (§5.3). **An arm run
before its class's floor is measured is void** — that is the v2 failure, promoted to a rule.

---

## 2. Selection policy — what to run next

Priority order, highest first:

1. **Blocking prerequisites** (`BACKLOG` status `PREREQ`). Nothing else runs until these clear.
   At v3 these are: the two reference arms (`P000`, `P001`), the incumbent replicate that
   establishes the floor, and `HA-02` (without which high-fold arms cannot be run at production
   seed counts — see §6).
2. **The pre-registered v3 backbone** — the `F` (inner-CV) then `N` (architecture) then `D` (data)
   ladder in `BACKLOG.md`, in order. This exists so the search cannot rationalise its way out of
   testing the decisive arms.
3. **Cache-paired arms at any time.** They are free and noise-free (§3b), so they never queue
   behind a refit arm.
4. **Agent-proposed arms** from step 10 of a prior wave, once they have a hypothesis, a class and a
   predicted direction.

**One change per arm.** An arm whose spec differs from its parent in more than one registered
dimension is rejected at step 7 regardless of score. Where a change is not independently
meaningful (an 84-day validation window is unreachable without the `min_test_days` change), it is
registered as **one bundle with its components enumerated** — never as separate arms and never
silently.

**Successive halving is retired.** Measured at v2: with 4-6 origins the sign-flip floor is
p = 0.125 and the subset-to-subset swing for an *unchanged* arm reaches 0.77. A screen at that n
cannot promote or demote anything. Arms run at the full 9-cutoff selection grid or not at all; cost
control comes from seed counts and `HA-02`, not from dropping origins.

## 3. Adoption rule (exact)

`incumbent := arm` **only if all six hold**:

| # | condition |
|---|---|
| A1 | `S(arm) - S(incumbent) > margin`, where `margin = max(0.01 + 0.002 * sqrt(n_arms_scored), floor(class, n_seeds))` from §3b |
| A2 | **both** an origin-block bootstrap LB > 0 **and** an exact origin-level sign test at p < 0.10 on the paired per-origin deltas |
| A3 | no top-10 burden country regresses by more than 0.02 WIS-skill |
| A4 | `S(arm) - S(incumbent) > 0` on the LOCKED confirmation blocks |
| A5 | adversarial review (§4) returns no blocking finding |
| A6 | the arm beats the `seasonal` baseline (OBJECTIVE §3b) |

**A2 requires both tests because at v2 they disagreed.** B-CAL's bootstrap gave
median +0.157, 95% CI [+0.083, +0.275] — a pass — while an exact sign test on the same 13 origins
gave **p = 0.4036** (7 wins of 13). The bootstrap resamples origins and recomputes a
burden-weighted mean, so it can return a tight interval while the per-origin direction is random.
At 6 selection origins the exact test is the binding one; report both, believe the exact one.

**A3 is a near-certain rejector for refit arms and must be read as such.** Under a zero true effect
and the measured per-country delta SD of 0.378, P(some top-10 country shows delta < -0.02) ~
**0.998**. It is informative for cache-paired arms, where fit noise cancels. For a refit arm, an A3
failure is only meaningful if the regressing country's delta exceeds that arm's per-country floor
(§3b) — otherwise record it as "A3 fail, within per-country noise" and let A1/A2 decide.

**Rejection is the default and is cheap.** Record it and move on. "Ship zero" is a legitimate
terminal state for the whole programme.

### 3b. Arm classes, and the floor each must clear

**This is the section v2 did not have, and its absence made 22 dugong-hours uninterpretable.**

| class | what changes | fit noise | cost |
|---|---|---|---|
| **C (cache-paired)** | post-processing only: bias correction, `psi_column`, smoothing, interval mode, scoring variants, NC1/NC3 | **none** — identical fits, deltas are exact | free |
| **R (refit)** | anything that changes the fit: inner-CV geometry (`F`), architecture (`N`), features/data (`D`), seeds, target | **yes** — must clear the measured floor | folds x seeds |

Rules:

1. **A class-C arm is always preferred when it can test the same hypothesis.** It answers at zero
   compute with zero fit noise. B-CAL, B-CAL2, the interval-mode work and NC1/NC3 were all class C
   and are the only v2 results that remain trustworthy.
2. **A class-R arm may not be scored until the floor is measured at its own seed count.** The floor
   is `|S(arm) - S(arm_replicate)|` for the SAME spec refitted from a **disjoint seed block**
   (`PSI_SEED_BASE`), on the same blocks. Report the per-country `|delta|` median and max too: at
   v2 the aggregate floor was 0.070 while **ETH alone swung 0.820**.
3. **Seeds are the floor's main lever, so spend there first.** The ensemble pools seeds by logit
   median, so the pooled-psi fit noise falls roughly as `1/sqrt(n_seeds)`. The v2 floor of 0.070
   was measured at `n_seeds = 3`; production and `P001` use 10. Predicted floor at 10 seeds
   ~ `0.070 * sqrt(3/10) ~ 0.038` — **this is a prediction, and measuring it is PREREQ
   `FLOOR-10`.** No class-R arm is interpretable until it is measured, and any arm scored at a
   different `n_seeds` than the incumbent is confounded by exactly this.
4. **Every class-R arm runs at the incumbent's `n_seeds`.** Seed count is a registered dimension; a
   change to it is its own arm (`AR-04`), not a cost saving.
5. **Same-seed pairing does NOT buy common random numbers.** `est_suitability()` is not
   reproducible across processes (lstm_v2 diverges ~0.1 `pred_smooth` / ~0.3 psi between identical
   cold serial runs; keras psi diverges up to 0.98 at production scale). Do not claim pairing
   removes fit noise for class R — only replication and seed-pooling reduce it.

### 3c. An inner-CV arm must state what the extra folds inform

Today the inner RW-CV produces exactly one number that reaches the deployed model:
`round(median(best_epoch))`, then a single refit on full IS with no early stopping
(`R/rolling_cv_suitability.R`, `.psi_fit_predict_rw_cv()`). **More folds therefore buy only a more
stable epoch estimate**, and that quantity saturates — 89 folds already estimate a scalar.

So a registered `F` arm must name, in its hypothesis, which of these it changes:

- **F-epoch** — more/better-placed folds for the same `median(best_epoch)` rule (the weakest bet,
  and the honest null: predicted direction 0 unless argued otherwise);
- **F-select** — the folds now choose something they did not before: per-fold *score*-based
  selection instead of pooled BCE `val_loss` (`CV-05`), a hyperparameter, or a trimmed/weighted
  epoch estimator;
- **F-ensemble** — the fold models themselves enter the prediction (bagging over origins) instead
  of being discarded.

An `F` arm that changes only the fold count and predicts a gain must say through which mechanism.
"More folds is more data" is not a mechanism: the training data per fold is unchanged.

## 4. Adversarial review (step 7)

Run by an agent that did not design or launch the arm (lane: `maintainer`). It must attempt to
**falsify** the result, not summarise it. Blocking findings:

- **Measurement validity.** Frozen weights (sha match)? Selection blocks only at step 4? Same cells
  for model and baseline? Same countries in both arms? Same `n_seeds`?
- **Floor.** Is the delta larger than the floor measured *for this class at this seed count*? Is
  the per-country claim larger than the per-country floor?
- **Provenance.** Did the arm reuse a psi cache whose `spec_hash` actually matches its registered
  spec (§5.7)? Were cells from two different specs pooled?
- **Confound.** Is the arm truly one change from its parent? Did the panel, the psi cache, the
  package version or the fold geometry move between parent and arm?
- **Direction.** Did the arm win in the direction predicted at PREREGISTER? An
  unpredicted-direction win is downgraded to a hypothesis, not an adoption.
- **Aggregation.** `S` is median-over-blocks then weight-over-countries, so it is **not** a
  weighted average of any subgroup decomposition. A claim about a subset (horizon bucket, tertile,
  region) must be computed on that subset, never inferred from the pooled number. Wave 17's
  retraction came from exactly this: psi beat the constant in all three target-variability
  tertiles while losing pooled.
- **Known-artifact check.** Does the win survive excluding NGA? Excluding the single
  best-performing country? A win carried by one country is not a win under this objective.

## 5. Guardrails (the autonomy price)

### 5.1 Frozen objective
`OBJECTIVE.md` and `weights_frozen.csv` are hash-checked at every scoring run. An agent may
**propose** an objective change in a wave report; it may not enact one. Changing it requires
bumping `objective_version` and re-scoring the incumbent, which invalidates all prior comparisons.
v3's grid re-anchoring was enacted **on explicit user instruction** and is recorded as such.

### 5.2 Negative control, every 5th wave
Inject arms that **must not win**. A valid negative control **destroys information the model is
meant to exploit while holding everything else fixed**:

- **NC1** psi shuffled within country (timing destroyed, marginal preserved)
- **NC3** psi replaced by U(0,1) noise (no information)

If either clears A1-A2, **the harness is broken** — halt, escalate, adopt nothing until resolved.
This is the only check that can detect a scorer bug flattering every arm equally. Both are class C,
so they cost nothing and there is no excuse for skipping them.

**Not a control: a simpler MODEL.** Replacing psi with its per-country mean does not remove
information — it substitutes climatology, which retains the country level. That is a **baseline**
to be beaten (now `seasonal`, OBJECTIVE §3b), not a control that must lose. Measured on A000 at
wave 8: NC1 -0.970, NC3 -3.128, real psi -0.387, country-mean constant **-0.258 (beat real psi)**.
Treating the constant as a control would have halted the programme over a true result; and the
pooled loss to the constant later proved to be an aggregation artifact (wave 17).

### 5.3 The holdout is write-once per arm
Confirmation blocks are read exactly once per arm, at step 6, after a selection win. The scorer
records `mode`. If confirmation disagrees with selection on **two** arms, halt: that is direct
evidence of selection-set overfitting and the split must be re-cut before continuing. With 6
selection and 3 confirmation origins, note that A4 is a low-power check by construction — it can
veto, it cannot certify.

### 5.4 Append-only ledger
`REGISTRY.tsv` is append-only and committed each wave. Rows are never edited or deleted; a
correction is a new row with `status=CORRECTION` referencing the original `arm_id`. Rows carry
`objective_version`: **v2 rows are superseded by the v3 re-anchoring and must never be compared to
v3 rows.**

### 5.5 No silent scope creep
An agent may not change the scoring pool, the horizon, the embargo, the baselines, the evaluation
grid, or the selection/confirmation split. These are objective parameters (§5.1).

### 5.6 New code on a fit-only path must be smoked before an arm launches
Some code is reachable only by a real `est_suitability()` fit: the prediction and manifest writers,
the bias correction, the ensemble aggregation, **and now the trunk registry (`N` arms) and the
epoch/ensemble decoupling (`HA-02`)**. No unit test touches them, so a defect there survives the
whole suite and surfaces only when an arm has already spent its compute.

Measured cost of learning this: a provenance block referencing `backend` — a variable that exists
only on `feature/psi-torch-port` — passed a field-name test, passed `devtools::test()`, and then
killed all 9 shards of an arm at the END of their first cutoff. **~13 dugong-hours discarded.**

**Rule: if a change touches a fit-only path, run `smoke_writers.R` before launching any arm.**
For an `N` (architecture) arm the smoke must be run **with that trunk selected** — a trunk that
builds under the smoke's 1-seed/2-epoch fixture is the minimum bar, and a trunk that has never been
built is not a registered arm.

### 5.7 psi-cache provenance is verified, never assumed (new at v3)
v3 reuses a psi cache built on 2026-07-11 under MOSAIC 0.63.0 by a different programme. Therefore:

- A scored arm must record the `spec_hash` of every cutoff file it consumed.
  `prefit_rolling_cv_psi()` writes these to `psi_manifest.json` and hard-errors on a mismatch;
  **that error is a feature and must never be worked around** by copying files between cache dirs.
- **Never pool cells from two caches with different `spec_hash` values into one `S`.** That would
  be a confound indistinguishable from an arm effect.
- The reused production cache is **read-only**. Arms write to their own `psi_cache_<ARM>/`.
- Record the MOSAIC version that produced each cache. A cross-version comparison must be
  registered as such, and `P001` (v0.63.0) vs a new arm (v0.90.x) is exactly that — the version
  delta is a known, registered confound on the `P000`/`P001` contrast, not a hidden one.

## 6. Budget, and the kill switch

| limit | value | on breach |
|---|---|---|
| dugong concurrency | `MOSAIC_PSI_CORE_BUDGET = floor(176 / n_processes)`, hard | refuse to launch |
| wall per wave | 8 h | kill the wave, record PARTIAL |
| disk free on dugong | must exceed 100 GB before launch | clean scratch, else halt |
| total waves | 30 | stop, write final report |
| total dugong-hours | 200 (**66 consumed through wave 20**) | stop, write final report |

### Measured cost model (use this to cost an arm before registering it)

Per-fold fit cost measured at `AR-01`: **0.36-0.52 min** (use 0.45); a final full-IS refit ~1.5 min.
Inner folds across the 9 production cutoffs, computed from `.psi_make_rw_cv_steps()`:

| geometry | folds/cutoff (2024-01 .. 2026-01) | total | cost @3 seeds | cost @10 seeds | @10 with HA-02 |
|---|---|---|---|---|---|
| `P000` pkg default (1 mo, 5 mo test, sub 6, midpoint) | 9..11 | **89** | 2.7 h | 9 h | **3.6 h** |
| `P001` prod-validated (1 mo, 4 mo test, sub 2, midpoint) | 25..31 | **255** | 6.8 h | 23 h | 6.4 h |
| `F4` 84 d stride, mty 4, 84 d window | 21..30 | **229** | 6.2 h | 21 h | **5.7 h** |
| `F1` 28 d stride, mty 4, 84 d window | 62..88 | **677** | 16 h | 53 h | **12.4 h** |
| `F3` 28 d stride, mty 2, 84 d window | 88..114 | **912** | 21 h | 71 h | 16 h |
| `F2` 14 d stride, mty 4, 84 d window | 124..176 | **1,351** | 31 h | 105 h | **22.5 h** |
| `F5` 7 d stride, mty 4, 84 d window | 247..352 | **2,697** | 61 h | 210 h | 43 h |

Wall time is that figure divided by the shard count (9 shards = one per cutoff).

**`HA-02` is the enabler for the whole `F` ladder, not an optimisation.** Today every seed re-runs
the entire fold loop, so cost is `folds x seeds` — and "more folds at the production seed count" is
unaffordable (F1 at 10 seeds = 53 h, over a quarter of the remaining budget for one arm). `HA-02`
decouples the two: epoch selection runs on `k` designated seeds (default 2), the remaining ensemble
members do refit-only at the chosen epoch. Cost becomes `folds x k + refits x seeds`. It is a
change to a fit-only path, so it is PREREQ, opt-in (`arch_control$epoch_select_seeds`, default NULL
= today's behaviour byte-unchanged), must pass `smoke_writers.R`, and must itself be run as an
equivalence arm against its parent (predicted direction **0**; accepted only if
`|delta| < floor`).

**F5 is out of budget at any seed count and is recorded as such** — it is in the table so nobody
re-derives it.

**Kill switch:** the presence of a file `STOP` in this directory halts the loop at the next step
boundary, before any launch. Agents check for it at steps 1, 3 and 8.

## 7. Stopping rules (autonomous termination)

Stop and write `FINAL_REPORT.md` when any of these fires:

| # | rule |
|---|---|
| T1 | **Success + plateau** — an arm has been adopted, and 5 subsequent consecutive waves adopt nothing |
| T2 | **Futility** — the `F` and `N` ladders are complete and no arm beats the incumbent, the `seasonal` baseline, or persistence on the confirmation blocks. *Stop the psi track* and report that the 12-week signal is not learnable with the current data and architecture family; redirect to `DA-04` (conflict covariates) / `DA-05` (subnational) |
| T3 | **Harness failure** — a negative control wins (§5.2) |
| T4 | **Overfitting detected** — two confirmation/selection disagreements (§5.3) |
| T5 | **Budget** — 30 waves or 200 dugong-hours (§6) |
| T6 | **Backlog exhausted** — no PREREQ, backbone or candidate arm remains, and step 10 has produced no new hypothesis for 3 waves |
| T7 | **Resolution failure (new at v3)** — the measured floor at production seed counts stays above the largest effect any remaining registered arm could plausibly produce. Unlike T2 this is a statement about the instrument, not the science, and it must be reported as such: the honest conclusion is "not measurable at this budget", not "does not work" |

T7 exists because v2 ended there without a rule for it, and the absence of the rule turned a
resolution problem into fifteen waves of interpretation.

Cross-lane rule: the agent that ran an arm may not review it.

## 9. Reporting

Each wave appends to `WAVES.md`: arms run, class, `n_seeds`, floor, `S` values, per-horizon
decomposition, decision, reason, new hypotheses, budget consumed. A wave that adopts nothing is
still reported — a run of rejections is the most informative signal the process produces, and
suppressing it is how a search talks itself into a false positive.

Every user-facing summary must carry two sentences that v2's did not always carry: **which floor
applies to the number quoted**, and **that the evaluation is a conditional hindcast, not a
forecast**.

Escalate to the user immediately, without waiting for the wave to finish, on: any §7 stop, any
guardrail breach, a negative-control win, or a proposed objective change.

## 10. Starting the v3 loop

1. **`P001`** — score the existing production psi cache on the frozen v3 grid. Class R but **zero
   fit cost**; read-only reuse of the OCV-4 cache (§5.7). This is the first number.
2. **`P000`** — refit the package-default psi at the same 9 cutoffs (~3.6 h with `HA-02`, 9 h
   without). `incumbent :=` whichever of `P000`/`P001` wins on selection; the contrast is the
   v7.3-vs-v7.4 result.
3. **`FLOOR-10`** — replicate the incumbent from a disjoint seed block. This is the number that
   makes every subsequent class-R arm interpretable, and it is PREREQ, not optional. At v2 it cost
   ~1 dugong-hour and was never run.
4. **`HA-02`** — build and smoke the epoch/ensemble decoupling, then run it as an equivalence arm.
   Without it the `F` ladder cannot run at production seed counts.
5. **`TRUNK-REG`** — build the trunk registry (§5.6) so `N` arms exist as registered specs.
6. Then the ladder in `BACKLOG.md`: `F` (inner CV) -> `N` (architecture) -> `D` (data).

**Until steps 1-3 exist, no arm can be adopted** — there is nothing to beat and no way to tell a
win from fit noise.
