# PROTOCOL — autonomous evolution of est_suitability() for 12-week forecast skill

**Mode: FULLY AUTONOMOUS with written stopping rules.** Agents propose, launch, score, adopt and
iterate without per-wave approval, reporting asynchronously. That makes the guardrails in §5 the
load-bearing part of this document, not boilerplate: an agent that both proposes and adopts will
drift toward whatever it can measure unless the objective is frozen and the harness is
continuously falsified.

**Objective:** `OBJECTIVE.md` (frozen, v1). **Ledger:** `REGISTRY.tsv` (append-only).
**Queue:** `BACKLOG.md`. **Incumbent:** the arm named in `INCUMBENT` at the top of `REGISTRY.tsv`.

---

## 1. The unit of work: a WAVE

One wave = one batch of arms taken to a decision. Target 4-6 h wall on dugong, so roughly one
wave per day unattended.

```
1 SELECT      pick arms from BACKLOG per the policy in §2
2 PREREGISTER append one REGISTERED row per arm BEFORE any fit runs:
              arm_id, parent, one-line hypothesis, the ONE change vs parent,
              predicted direction (+/-/0), spec hash, objective_version
3 RUN         launch on dugong under the budget in §6
4 SCORE       compute S(arm) on SELECTION folds only; write SCORED row
5 GATE        if S(arm) - S(incumbent) > margin AND bootstrap LB > 0
              AND no top-10 regression > 0.02  ->  proceed to 6, else REJECT
6 CONFIRM     score on the LOCKED confirmation folds; write CONFIRMED row
7 REVIEW      adversarial pass (§4) by an agent that did not run the arm
8 DECIDE      ADOPT (incumbent := arm) or REJECT, with reason, appended to REGISTRY
9 PROPOSE     append new candidate arms generated by what was learned to BACKLOG,
              each with a hypothesis and a predicted direction
```

**No step may be skipped or reordered.** An arm with no REGISTERED row predating its SCORED row
is void. An arm whose CONFIRMED row predates its SCORED row is a protocol breach (§5.3).

---

## 2. Selection policy — what to run next

Priority order, highest first:

1. **Blocking prerequisites** (`BACKLOG` status `PREREQ`). Nothing else runs until these clear.
2. **The pre-registered backbone** — the Phase 1/2 ladder from `../plan_psi_12wk/PLAN.md`, in
   order. This exists so the search cannot rationalise its way out of testing the decisive arms.
3. **Successive halving among open candidates.** Run the top-k BACKLOG items at reduced cost
   (1 cutoff, 3 seeds); promote the best half to full cost (3 cutoffs, 5 seeds). Cheap arms first
   when expected value ties.
4. **Agent-proposed arms** from step 9 of a prior wave, once they have a hypothesis and a
   predicted direction.

**One change per arm.** An arm whose spec differs from its parent in more than one registered
dimension is rejected at step 7 regardless of score. The G-vs-E episode — a +0.0017 difference at
p ~ 0.61 across four simultaneous changes, adopted as a win — is the failure this rule exists for.

---

## 3. Adoption rule (exact)

`incumbent := arm` **only if all five hold**:

| # | condition |
|---|---|
| A1 | `S(arm) - S(incumbent) > margin` on SELECTION folds, where `margin = 0.01 + 0.002 * sqrt(n_arms_scored_so_far)` |
| A2 | bootstrap lower bound of the paired per-(country x fold) delta > 0, block-resampled over origins |
| A3 | no top-10 burden country regresses by more than 0.02 WIS-skill |
| A4 | `S(arm) - S(incumbent) > 0` on the LOCKED confirmation folds |
| A5 | adversarial review (§4) returns no blocking finding |

The `sqrt(n_arms)` term in A1 is the multiplicity price: the more arms tried, the larger the
effect required. It is not a substitute for A4; it is a floor under it.

**Rejection is the default and is cheap.** Record it and move on. "Ship zero" is a legitimate
terminal state for the whole programme.

---

## 4. Adversarial review (step 7)

Run by an agent that did not design or launch the arm (lane: `maintainer`). It must attempt to
**falsify** the result, not summarise it. Blocking findings:

- **Measurement validity.** Did the scorer use the frozen weights (sha match)? Selection folds
  only at step 4? Same cells for model and baseline? Same countries in both arms?
- **Confound.** Is the arm truly one change from its parent? Did the panel, the psi cache, the
  package version or the fold geometry move between parent and arm?
- **Direction.** Did the arm win in the direction predicted at PREREGISTER? An unpredicted-direction
  win is downgraded to a hypothesis, not an adoption.
- **Magnitude vs noise.** Is the delta larger than the same-arm replicate spread? keras psi
  diverges by up to 0.98 run-to-run at production scale, so a delta smaller than the within-arm
  seed spread is noise, whatever the bootstrap says.
- **Known-artifact check.** Does the win survive excluding NGA? Does it survive excluding the
  single best-performing country? A win carried by one country is not a win under this objective.

## 5. Guardrails (the autonomy price)

### 5.1 Frozen objective
`OBJECTIVE.md` and `weights_frozen.csv` are hash-checked at every scoring run. An agent may
**propose** an objective change in a wave report; it may not enact one. Changing it requires
bumping `objective_version` and re-scoring the incumbent, which invalidates all prior comparisons.

### 5.2 Negative control, every 5th wave
Inject arms that **must not win**. A valid negative control **destroys information the model is
meant to exploit while holding everything else fixed**:

- **NC1** psi shuffled within country (timing destroyed, marginal preserved)
- **NC3** psi replaced by U(0,1) noise (no information)

If either clears A1-A2, **the harness is broken** — halt, escalate, adopt nothing until resolved.
This is the only check that can detect a scorer bug flattering every arm equally.

**Not a control: a simpler MODEL.** Replacing psi with its per-country mean does not remove
information — it substitutes per-country climatology, which retains the country level. That is a
standard forecast **baseline**, to be beaten, not a control that must lose. Measured on A000 at
wave 8: NC1 -0.970 and NC3 -3.128 against real psi -0.387 (scorer discriminating correctly), while
the country-mean constant scored **-0.258 and BEAT real psi**. Treating it as a control would have
halted the programme over a true result.

**Reported baseline (added wave 8):** every arm reports `S` against the per-country constant as
well as against persistence. **An arm that cannot beat a flat per-country constant is not adopted
whatever its `S`** — if the model's time-variation is net-harmful, a better-scoring variant of it
is not an improvement worth shipping.

### 5.3 The holdout is write-once per arm
Confirmation folds are read exactly once per arm, at step 6, after a selection win. The scorer
records `mode` in the registry. If confirmation disagrees with selection on **two** arms, halt:
that is direct evidence of selection-set overfitting and the split must be re-cut before
continuing.

### 5.4 Append-only ledger
`REGISTRY.tsv` is append-only and committed each wave. Rows are never edited or deleted; a
correction is a new row with `status=CORRECTION` referencing the original `arm_id`.

### 5.6 New code on a fit-only path must be smoked before an arm launches
Some code is reachable only by a real `est_suitability()` fit: the prediction and
manifest writers, the bias correction, the ensemble aggregation. No unit test touches
them, so a defect there survives the whole suite and surfaces only when an arm has
already spent its compute.

Measured cost of learning this: a provenance block referencing `backend` -- a variable
that exists only on `feature/psi-torch-port` -- passed a field-name test, passed
`devtools::test()`, and then killed all 9 shards of an arm at the END of their first
cutoff. **~13 dugong-hours discarded.** A field-name check cannot see an unbound
identifier, and `findGlobals` (added afterwards) still cannot see a runtime failure
inside the block.

**Rule: if a change touches a fit-only path, run `smoke_writers.R` before launching any
arm.** It is a 1-seed, 2-epoch, short-window fit into a temp directory that asserts the
four output files exist and the manifest carries its required provenance keys non-NULL.
Minutes, against hours of arm compute. The A000 smoke earned its keep the same way --
it is what exposed the zero-width-interval artefact before 18 cutoffs were scored on it.

### 5.5 No silent scope creep
An agent may not change the scoring pool, the horizon, the embargo, the baseline, or the
selection/confirmation split. These are objective parameters (§5.1).

## 6. Budget, and the kill switch

| limit | value | on breach |
|---|---|---|
| dugong concurrency | `MOSAIC_PSI_CORE_BUDGET = floor(176 / n_processes)`, hard | refuse to launch |
| wall per wave | 8 h | kill the wave, record PARTIAL |
| disk free on dugong | must exceed 100 GB before launch | clean scratch, else halt |
| total waves | 30 | stop, write final report |
| total dugong-hours | 200 | stop, write final report |

**Kill switch:** the presence of a file `STOP` in this directory halts the loop at the next step
boundary, before any launch. Agents check for it at steps 1, 3 and 8.

---

## 7. Stopping rules (autonomous termination)

Stop and write `FINAL_REPORT.md` when any of these fires:

| # | rule |
|---|---|
| T1 | **Success + plateau** — an arm has been adopted, and 5 subsequent consecutive waves adopt nothing |
| T2 | **Futility** — the Phase 2 backbone is complete and the incumbent still does not beat persistence on the confirmation folds. *Stop the psi track* and report that the 12-week signal is not learnable with the current data; redirect to DA-04 (conflict covariates) / DA-05 (subnational) |
| T3 | **Harness failure** — a negative control wins (§5.2) |
| T4 | **Overfitting detected** — two confirmation/selection disagreements (§5.3) |
| T5 | **Budget** — 30 waves or 200 dugong-hours (§6) |
| T6 | **Backlog exhausted** — no PREREQ, backbone or candidate arm remains, and step 9 has produced no new hypothesis for 3 waves |

## 8. Agent lanes

| lane | owns |
|---|---|
| `ml-scientist` | arm design, psi science, step 9 hypothesis generation, architecture and feature arms |
| `swe` | harness changes, dugong orchestration, fold-loop parallelism, thread budgets |
| `statistician` | the scorer, bootstrap, multiplicity, negative controls, the split |
| `data-engineer` | panel fixes (DA-01, DA-02), new covariate ingestion (DA-04) |
| `maintainer` | step-7 adversarial review; must not be the lane that ran the arm |
| `calibration-doctor` | Phase 4 downstream propagation only |

Cross-lane rule: the agent that ran an arm may not review it.

---

## 9. Reporting

Each wave appends to `WAVES.md`: arms run, S values, decision, reason, new hypotheses, budget
consumed. A wave that adopts nothing is still reported — a run of rejections is the most
informative signal the process produces, and suppressing it is how a search talks itself into a
false positive.

Escalate to the user immediately, without waiting for the wave to finish, on: any §7 stop, any
guardrail breach, a negative-control win, or a proposed objective change.

---

## 10. Starting the loop

1. Clear the PREREQ items in `BACKLOG.md` (DA-01, DA-02) and the Phase-0 harness work. Nothing
   downstream is trustworthy until the panel has zero duplicate `(iso_code, date)` rows.
2. Score the incumbent (current production psi: v7.3, concurrent target, 20-fold CV) under the
   frozen objective. This is `arm_id = A000` and it is the number everything is measured against.
3. Start the wave loop (`/loop` with dynamic pacing is the natural mechanism: runs are ~4 h, so
   long intervals with a wake on job completion).

**Until step 2 exists, no arm can be adopted** — there is nothing to beat.
